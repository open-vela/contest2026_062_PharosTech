# 第二部分 Nyabula AI 智能硬件创新产品

[返回参赛主页](../../README.md) · [原生平台](../platform/README.md) · [系统架构](ARCHITECTURE.md) · [扩展开发](EXTENSIONS.md) · [验证记录](../validation/README.md)

Nyabula 把平台能力组织成可以使用和继续扩展的桌面 AI 设备：用双眼反馈状态，用语音或浏览器执行日常操作，让模型生成新的小工具，再用权限、持久化和升级机制管理这些能力。

## 产品主线

| 使用场景 | 用户得到什么 | 实现位置 |
|---|---|---|
| 日常交互 | 聆听、识别、回答、播报与双眼反馈 | 原生语音状态机、Eye、AMP计算服务 |
| 做一件实际的事 | 计时、音量、表情、记忆、闹钟、待办；结果可核对 | Nyabot / 官方ai_agent、Core工具与审批 |
| 增加一个工具 | 用自然语言生成、安装、试用、反馈和修复插件 | Agent authoring、设备签名、NyaUI |
| 桌面音乐 | 两台蓝牙设备在线选源，16段EQ与USB低音 | Bluetooth、公共DSP与双输出生命周期 |
| 设备管理 | 配网、QR登录、成员权限、Cloud、模型与OTA | 本地面板、CLI、持久状态和nbootctl |

## 语音与智能体

完整回合为 **KWS唤醒 → ASR识别 → Agent处理 → 工具执行或回答 → TTS合成 → 播放**。麦克风、预录、回合状态、扬声器和眼睛由 openvela 管理。语音模型在 Linux 计算域运行，在线模型仍沿用相同的设备工具机制。

- 本地文本：MiniCPM5-1B W4A16 / RKLLM 1.3；明确设备意图使用规则与必要的单工具补参，普通聊天单独走模型。
- 在线文本：MiMo 2.6 Flash / Pro，支持普通API与Token Plan配置及思考偏好。
- 语音：端侧KWS/ASR/Melo路径与云ASR/TTS适配；云语音接口使用对应2.5系列模型ID。
- 控制：取消、deadline、预录采样位置、窗口lease、网络与PCM输出分离，以及执行步骤展示。

默认播报时闭麦；全双工AEC和随时插话尚未完成。完整功能回合有现场确认，真人低唤醒率和远场质量仍是当前问题。B92附加唤醒词/灵敏度/独立测试接口属于[近期验证](../validation/README.md#近期实机与软件证据)。

## Agent 在设备上创建新功能

开启“自动生成与安装”后，可以要求“做一个本地记账本”“加分类筛选”或“修复负数输入提示”。模型读取当前契约和源码，生成插件，经过设备签名安装，再通过真实 UI 事件与数据结果检查行为。失败结果返回模型继续修复。

三个实例覆盖不同能力：

- **记账本**：金额校验、分类/备注、合计、筛选、按条删除与清空；更新与重启后保留数据。
- **传输计算器**：GB/GiB、MB/s/Mbps、效率、预计时长与历史；模型根据真实按钮层级错误继续修复。
- **设备体检**：只读系统、音频、蓝牙和USB状态；显示单位并通过真实刷新事件获取新值。

生成包限定 `agent-*` 命名空间与可用权限，更新使用 `baseVersion`。候选失败恢复旧代码、私有数据与授权。模型曾出现没有工具调用却声称完成的情况，因此页面同时展示 **设备执行记录**，将“实际执行”“已拒绝”“只有文字”区分开。

## 运行时 Skill

## 音频与蓝牙音乐

TTS、蓝牙A2DP与文件播放共用公共DSP：输入采样率转换到48kHz，经过1—16段类型化EQ、全频或LR4分频、增益/相位/延迟及采样峰值限幅，再送往ES8388和USB低音。

- **调音**：PEAK/LOW_SHELF/HIGH_SHELF，实时预览、撤销、保存预设、配置穿重启；保留旧四段接口兼容。
- **耳机路由**：实际输出为耳机时暂时停用 2.1 低音与分频；扬声器或双输出恢复原设置，保存的 EQ 和分频值不变。B108 四种路由已板测。
- **双输出**：板载高通与低音低通可独立设置；两套设备时钟用队列反馈校正，支持热开关、软件暂停/恢复、全局音量与静音。
- **双设备蓝牙**：Windows与OPPO可同时在线，选择唯一媒体源；两端元数据、音频和按键事务隔离。B88完成暂停/恢复/上一首/下一首及实际切源试听，用户确认无串音或爆音。
- **流式播放**：网络生产者与PCM消费者解耦，修复长句后段供数劣化；B86三轮USB欠载均为0，30%音量接回低音后听感通过。

HFP真实双向通话、USB Mic IN、完整声学校准与所有音量/功放增益组合尚需独立验收。采样峰值限幅不等于扬声器热/位移保护。

## 双眼与场景设计

Eye由Display提供物理双屏，由Core管理来源和优先级：13类表情、25类历史Scene、自动/单眼眨眼、凝视、虹膜与异瞳、字幕、lease/release。高优先级闹钟等场景可覆盖普通请求；结束后只释放自己的场景。

Agent运行时采用真实步骤数与不定进度，没有总量时不虚构百分比。认证的 `/eyes/stream` 让面板读取设备渲染页；普通产品保持硬TE，无屏评审配置使用软件TE并开放受控eyeprobe。

最新B93/B94将天气、音乐、音频、EQ、低音、通话状态、网络、设备、系统、陪伴等场景绑定到设备服务，并验证无浏览器推送时秒表仍前进。这部分已随代码PR #110合入主线；实体屏幕最终像素验收也未完成。本轮隐藏电量、健康/rPPG与家居入口；身份与软件隐私能力见下。

## 灯光、摄影与身份

本轮代码支持四区灯光独控、瞳色同步或互补、动画及音乐律动，开机清零并支持休眠。B103 的 openvela 摄像头采集、H.264 编码和预览经用户确认画面正常；B105 的摄像头和麦克风软件隐私开关可独立控制并穿重启保存。

B106 真人检测框的位置与移动经用户确认；B108 身份模型处理实际帧正常，用户主动登记一条人脸。声纹模型已就绪，身份页提供登记、测试、删除和仅回应主人，真人登记与匹配本轮未验收。物品学习追踪仍有模型加载错误，B109更新面板已隐藏入口，合入的代码默认关闭API和Agent入口、代码保留。五点校准后的实体猫眼跟随尚待实测。

Cloud 媒体中继已通过临时数据库测试；真实远程画面、双向听说与 Agent 获批后的 MiMo 看图仍需联调。

## 原生服务与交互设计

| 服务 | 已实现内容 | 使用边界 |
|---|---|---|
| 时间与记录 | 倒计时、秒表、睡眠计时、多闹钟/重复、日历、任务、记忆 | SQLite/CAS持久化；按服务测试区分sim与板测 |
| 时间同步 | RTC开机读取、SNTP校正与RTC回写 | 精度样例不是长期漂移测量 |
| 天气与简报 | 和风天气/Open-Meteo、当前/7日/24小时、缓存/过期提示、简报 | Open-Meteo为模式估计；缺预警不显示“无预警” |
| 陪伴与通知 | 陪伴配置、主动任务入口、通知去重 | 不将其描述为情绪识别或健康诊断 |
| USB文件共享 | 默认关闭/只读，认证HTTP目录/上传/下载、范围请求 | 软件/sim已测；实物盘完整验收待补；不是SMB |
| 系统维护 | 网络、模型、音频、状态、OTA、QR登录与密码重置 | CLI和面板共用校验/持久化；密码重置撤销旧会话 |

页面不是计时、天气或状态的真源，浏览器关闭后设备服务仍拥有自己的生命周期。所有控制端通过同一产品RPC与身份授权访问服务。

## 签名插件与成员权限

QuickJS/WAMR运行时提供声明能力、Broker、Ed25519签名、信任与撤销、版本槽、健康/隔离、配额和异步调度。插件可以发布NyaUI组件树或隔离HTML页，由宿主切换视图；事件只能调用已发布绑定。

owner、family、guest由设备后端执行权限检查。真实板测覆盖guest只读、family发送UI事件但不能授权/改密码、角色变更使旧会话失效、撤销后拒绝连接。插件声明权限不等于主人已授权。

这是受管理的可信插件运行环境，未提供对任意恶意代码的强内存隔离。具体开发方式见[扩展指南](EXTENSIONS.md)。

## 本地面板与远程连接

- **本地面板**：设备自托管HTTP/WebSocket、NyaLink、配网、插件/Nyabot/功能页、模型与升级；CLI可恢复忘记的面板密码，QR可在眼屏显示并退出。
- **Web恢复**：监听循环出错后退避重建，主动停服保持停止；B78覆盖16次HTTP中断和手动停启。强杀整个任务与内存破坏不属于该恢复循环。
- **Cloud**：K7主动连接中继，完成注册、认领、设备密码鉴权、远控、重启恢复。WSS实测成功证书、错误主机名拒绝和服务恢复自动重连。
- **MCP**：原生出站HTTPS工具逐次审批；入站loopback/隧道、限期scope凭据、隔离会话与撤销已有真机验证。
- **渠道**：微信iLink、飞书等适配已有代码与协议测试；真实账号扫码收发尚未完成验收。
