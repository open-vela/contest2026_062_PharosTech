# 故障矩阵与案例

## 地址域先于优化

K7物理4GiB从0x40000000开始，末端已超过32位地址；PL330和项目当时的32位ADMA2不能使用全部普通堆。DMA专用低地址heap是可达性约束，不是“ARM64要32位指针”。先核对目标引擎是否支持高位地址、IOMMU是否启用及映射生命周期。

buffer可能只在头尾与其他对象共享cache line。RX invalidate若覆盖CPU尚未写回的邻接数据会破坏无关对象；采用API要求的隔离/对齐，必要时bounce。descriptor和payload分别同步，硬件完成后才将数据所有权交回CPU。

## 成功案例

团队PR54中，块层4KiB至512KiB请求常因未按cache line对齐回退PIO。驱动增加低4GiB的512KiB bounce后，64MiB/512KiB读请求约75.5MiB/s，而旧PIO约12.6MiB/s；重复8MiB读取cmp一致。这证明指定读路径，不证明写入/所有对齐模式都通过。

## 反例

xHCI cancel通知返回不表示DMA已静止。若先释放ring或数据，控制器仍可能写入被复用内存。NuttX fork PR10将停止DMA/ring处理置于waiter与异步callback通知之前；无法证明静止时停止控制器，不用超时一到就free的办法回避竞态。

## 最小可区分矩阵

| 维度 | 要覆盖 |
|---|---|
| 对齐 | 自然对齐、cache line两侧偏移、头尾共享line |
| 长度 | 1个有效单元、最大descriptor前/等于/后、跨硬件边界 |
| 地址 | 最低/最高可达区、不可达区应拒绝或回退 |
| 模式 | PIO与DMA同输入、直传与bounce同输入 |
| 生命周期 | 自然完成、timeout、cancel、拔出/复位后再次操作 |

采用固定位模式、递增序号、CRC或整文件hash；写测试仅使用已指定临时文件/测试区，不覆盖未知扇区。记录失败位置和预期/实际字节，不只报中断计数。

验收：给一份“IRQ完成但尾部32字节错误”的样本，应先检查边界/cache所有权；给“用户缓冲区未对齐”，应保留合法fallback而非删除保护。
