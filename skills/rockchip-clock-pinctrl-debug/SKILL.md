# Rockchip 时钟与引脚排错

先取得同一控制器、同一板版本的“请求值—寄存器值—实际行为”三份记录。不要把clock API返回成功当成输出频率已改变。

1. 从目标IP向上追父时钟、mux/divider/gate、reset、PD及IOC访问时钟。区分功能时钟与总线时钟；已有可用链不反复开关验证。
2. 核对寄存器写语义：hiword-mask、W1C、只读状态与普通RW分别处理。板级电源和引脚选择留在板层。
3. 比较loader遗留状态、首次驱动初始化、open/close与热重启。每个快照记录时刻；静态值相同不证明上电窗口相同。
4. 用可区分的观测验证设置：实际分频链、独立时钟测量、可解释的传输时间；其他clock视图矛盾时保留矛盾，不挑一个当真值。
5. 失败时按已取得资源反序回收，确认不会关闭同域其他用户的共享时钟。

按现象查[判别与案例](references/runbook.md)，按版本定位[源码及证据](references/sources.md)。

交付依赖链、改动的寄存器/时钟节点、前后观测与冷/热启动范围。只修本次命中的依赖，不顺手改整棵时钟树。
