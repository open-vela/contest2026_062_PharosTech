# 状态与网络反例

## 最小端到端流程

空配置启动AP；手机取得租约；浏览器加载设备托管面板；认证后选择SSID；设备连接且保存；AP关闭/页面给出新地址；手机换回网络；重启后设备重新联网。每步失败有可解释回退，不能靠PC模拟器预置数据补足。

## 项目实际失败链

- product编过却rcS未启动服务；可执行文件存在不等于开机运行。
- FAT长文件名没开导致Core持久化路径失败；父目录不存在还可能返回ENOTDIR而非ENOENT。
- 没开TCP backlog导致Web一个连接都接不到；帧头单独成段、无写缓冲造成延迟；RX队列/乱序能力又影响入站上传。要分层，不用前端无限重连掩盖。
- `eyes.scene.hide`遗漏必需params对象被EINVAL拒绝，提交返回又忽略；本地visible变false不代表屏幕撤了二维码。
- WiFi host IP只在发包时同步，别人先找设备容易失败；主动ping通不等于被动可达。

9月19日手机实际配网、面板密码登录和自托管完成；9月20日记录30/30突发、4×20并发与90s浸泡。它们是短窗口，不是长期在线保证。部分新页面只有typecheck/单测，须按真实Core逐项走查。

ADB forward曾有microADB释放后使用引发整机复位；修前同签名6次，补丁后20余会话未复位。不要因此断言所有整机卡死都解决，更不要把它归为普通WebSocket网络错误。

## 验收对照

错误密码后再次正确配网；AP断开/路由器重启；未登录/过期会话/CAS旧revision；手机切网；两客户端同时改状态；大文件传输后小请求仍可用。登录/配网测试用合成凭据，日志不回显真实密码。没有请求公网发布，不改变监听暴露范围。
