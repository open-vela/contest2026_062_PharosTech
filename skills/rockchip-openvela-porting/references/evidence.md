# 证据与置信

## 新记录模板

```markdown
## [YYYY-MM-DD] 一句话结果
- 场景: 板卡/版本、当前里程碑、固件标识和前置条件
- 操作: 在哪台机器、哪个目录执行哪些命令；参数可复制
- 结果: 原始输出/错误全文、返回值、哈希和关键测量数值
- 结论: 本次证明了什么、未覆盖什么、是否推翻旧假设
- 置信: 编译通过
```

最后一行按事实选“实测确认”“编译通过”或“仅推断”之一。
复杂实验应按结论拆条；不要把板测成功、文档推断、待测试修改混为一个等级。
串口号、波特率、DDR大小、EL、交接地址、tok/s 等关键值必须保留上下文。

## 三个等级的边界

- 实测确认：在指定真机观察到指定结果。记录持续时间、次数、数据量、
  对端型号及版本。短时测试不能推出长期可靠性。
- 编译通过：写明宿主单测、sim运行、目标交叉编译还是完整链接。
  例如 ASan 测试通过不能替代 DMA 或真实中断验证。
- 仅推断：TRM/DTS/源码和经验得出的判断。多来源吻合仍不是板测。

旧日志中的“实测确认(sim)”保留其原文，导出案例时明确它只是模拟器验证。
带错误结果的实验可以是有效实测；不要为了通过脚本把失败改写为成功。

## 来源与迁移

每个抽取到 Skill 的案例须有日期、原始标题、关键原文、适用环境和边界。
公开源码引用固定版本；内部原始记录未随包分发时明确声明。
若实验同时改了四个变量，只能说联合配置有效；除非有消融实验，
不能宣称某个变量是唯一根因。

保留历史记录，在新的派生摘要标明修正及对应证据。最新章节不一定
代表更强证据：编译过的新方案也可能尚未替代已板测的旧方案。

## 审计脚本

脚本检查真实日历日期、五个字段、字段重复、置信标签；识别 UTF-8 BOM、
全角冒号、多行内容和围栏代码块，遇到下一节结束当前记录。
以四位年份加连字符开头的日期标题也会检查格式，例如 `[2026-9-17]`
报非法日期，不静默漏掉；`[2026-09-17 续2]`仍按历史后缀处理。
围栏结束只接受相同符号、不短于开头且无尾部文本的行；代码里的字段不是元数据。
历史缺字段/混合置信/旧标签为警告；重复字段、非法日期/标签为错误。
置信度取该字段第一行，不从“尚未实测确认”等字串提取肯定结论。

普通模式仅错误导致非零退出；strict 模式警告也会失败。
退出码 0 为结构合格，1 为发现问题，2 为输入错误或无记录。
JSON 报告可用于后续审阅，但不能认证记录真实、硬件行为正确、无敏感信息
或符合参赛采集规范。人工核查始终需要原件。

实测日志审计脚本和组委会 AI 会话采集器是两种工具。AI JSONL 的导出、
脱敏和校验必须遵循官方流程，不能用本脚本修改或替代。
