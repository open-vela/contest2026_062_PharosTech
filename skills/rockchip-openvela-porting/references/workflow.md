# 启动与驱动验收节点

以下是依赖和验收节点，不给项目重新定义 M1–M7 编号，也不强制按标题顺序
重写现有启动汇编。用户只要求修已有驱动时，从相应节点进入。

## 先固定研究对象

从 TRM/数据手册提取寄存器与访问语义，从原理图确认电源和连接，
从实际设备 DTS/DTB、启动日志和运行态取证得到部署事实。
记录 SoC revision、板卡 revision、文档版本和命令来源。
IRQ 必须区分 SPI 索引与 GIC 绝对号。

在 openvela 原版 manifest 工程里找相同 IP 的移植作为模板。
独立板级代码经团队 manifest/linkfile 接入，不直接覆盖共享构建树。

## 构建确实包含本次代码

最小配置只启用启动所需架构、串口、NSH、内存配置。
保存 resolved manifest、工具链版本、命令/退出码、ELF入口和产物哈希。
仅“编译通过”，即使文件名叫 release 也不代表上板。
团队仓 SHA 不包含其他 repo 的版本、未提交补丁或外部 blob；按 runbook
记录这些输入。Make/CMake 分别验证；相同配置名不保证用了同一份 `.config`。

## 首个可观察字节

先证明 loader 真的交接到了正确镜像。使用早期轮询 putc，避免依赖
调度器、堆和中断。无输出时依次区分：
实际启动介质/版本 → 入口前元数据 → load/entry → EL/栈 →
UART地址/时钟/引脚/波特率 → 完整串口 console 配置。

## 异常 内存 中断 与 NSH

确认 GIC 版本和 distributor/CPU interface/redistributor 地址。
确认设备内存属性、页表和 Cache，再验证异常、generic timer 与中断。
记录 timer 实际频率；必要时检查 EL3 设置是否向后续阶段传递。
轮询输出通后再用完整驱动验证命令输入、输出及重启。

## 按需增加并发

UP 成功不证明 SMP。需要 SMP 时分别验证 PSCI CPU_ON、各核栈、
中断/定时器状态及驱动锁。

AMP 前先形成 CPU/RAM/IRQ/clock/外设所有权表。保留 OP-TEE 等固件区域；
双域不能同时初始化同一个共享控制器。确认通知、vring、端点发现和
重启恢复合同，不假定厂商 rpmsg-mbox 等同标准 OpenAMP。

## 外设纵向闭环

按依赖推进：时钟/复位/引脚 → 低速外设 → 存储 → 网络/USB →
显示/音频 → 加速器/产品服务。已有可靠板测的依赖可直接复用。

每个驱动至少覆盖初始化、一条有效操作、错误路径、重复操作和错误后的
下一次操作。PIO 工作后再加中断/DMA；DMA 完成中断不等于数据正确。
关闭上一阶段时说明未覆盖的模式，例如24位音频、热拔插或长时间运行。
