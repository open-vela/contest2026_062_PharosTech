# 选择实验界面，继续使用同一台设备

设备页面进入「客户端设置 → 界面风格」，可选星云、仪器或经典。
Cloud 在登录页左上角或「账号 → 外观」选择。首次访问仍默认经典。
风格、深浅模式、色盘和布局偏好仅保存在当前站点的浏览器中。

## 三种外观共用业务与权限

- **星云**：猫眼主视觉、玻璃面板、浮动导航；眼睛页接入共享的虹膜、场景、环境光校准和实屏镜像组件。
- **经典**：保留现有 Material 布局和业务页面，继续作为首次访问的默认风格。
- **仪器**：点阵读数、硬件按键和监视器边框；桌面、平板、手机各有外壳。

`apps/nyabula/src/skins/registry.ts` 选择外壳与主页/眼睛/连接页。
其余路由使用同一份业务页面，由 `packages/ui/src/skins/` 提供统一组件样式。
没有把设计实验室的假数据或模拟操作接入产品。

设备构建继续使用原有密码门禁、配网裸页和 hash 路由。
切换皮肤不会更换设备、权限、模型配置或配对凭据。
原生二维码场景继续显示已认证的设备实屏流，其余场景使用与板端对齐的 EyeEngine。

## 页面范围

| 端 | 页面与操作 |
|---|---|
| 设备 | 连接、密码登录/设置、WiFi 配网、主页、眼睛控制、功能目录和详情 |
| 设备 | Nyabot 对话及各配置区、MiMo 配置、插件列表/详情/权限、工作区设置 |
| 设备 | 设备概览、网络、云中继、权限、存储、模型、更新、日志、关于 |
| 设备 | Cloud 账号和设备统计、客户端皮肤/色盘/深浅模式/布局 |
| Cloud | 登录/注册、总览、设备认领/解绑、搜索/筛选/排序、详情和中继控制 |
| Cloud | 7/30 天流量汇总、每日明细、当前会话事件、账号和外观 |

Cloud 流量来自 `/devices/{id}/stats`，单位为帧与在线小时；不将帧数换算成虚构字节数。
事件页记录本次登录后的操作与观察到的在线变化，最近 200 条；退出后清除。
服务端现有 v1 协议不提供付费套餐、设备额度或个人访问令牌管理，因此界面不显示实验稿的虚构额度和令牌。

## 本地运行与设备构建

在本目录运行：

```sh
pnpm build:packages
pnpm --filter @nyabula/app dev
pnpm --filter @nyabula/console dev
```

设备 WebUI 默认端口 5180，Cloud 默认端口 5174；开发服务器将 `/api` 代理至本机 8080。
Cloud 使用现有 `Shared/protocol/cloud.md` v1 REST/中继接口。
前端没有把模拟器数据当成设备数据的降级路径。

```sh
pnpm typecheck
pnpm --filter @nyabula/eye-engine test
pnpm --filter @nyabula/app build:device
pnpm --filter @nyabula/console build
```

设备产物在 `apps/nyabula/dist-device/`。部署时先上传 `assets/`，最后更新 `index.html` 和其 gzip 文件；保留上一个入口和其引用资源即可恢复。
Cloud 产物在 `apps/console/dist/`，需与对应 API/中继反向代理部署在同一站点。

## 验收使用真实能力边界

基础 Go 模拟器可验证连接、配对、表情场景、插件页面、Cloud 认领和中继。
原生 Core 的闹钟/计时/记忆/模型/音频等正向动作必须在支持相应能力的设备上验证。
不支持的功能应显示原因并禁用写入；错误请求不得伪装成成功或无限显示载入中。

皮肤验收包含实际浏览器截图、桌面/平板/手机布局、状态回读和刷新持久化。
本轮逐项结果与未覆盖项随验收报告交付，不以构建成功代替操作验收。
